2. Project Objective

I want to build a desktop application called:

Landing Page & Email QA Mapper

In my company, clients provide landing page URLs. Our developers create landing pages and email pages based on the client's content.

As a QA tester, my responsibility is to verify that the Title and Abstract on our landing page and email page match the original client-provided content.

The problem is that our Excel files contain many columns, but we only need a few specific columns.

I want an application that:

Uploads an Excel file.
Automatically reads all Excel column names.
Allows me to select which columns contain the required URLs and reference content.
Visits the selected URLs.
Extracts only the required Title and Abstract.
Compares our landing page and email content against the original reference.
Shows missing, extra, and changed content.
Generates a downloadable Excel QA report.
3. Excel Upload and Dynamic Column Mapping

My Excel files may contain many columns.

The application must NOT use hardcoded Excel column names.

After uploading an Excel file, it should:

Read all headers from the first row.
Display all available column names in dropdown menus.
Allow me to choose the appropriate columns.
Support different Excel structures for different projects.

The application should support these fields:

Application Field	Excel Column
Client Landing Page URL	Selected by me
Our Landing Page URL	Selected by me
Our Email HTML URL	Selected by me
Original Title	Optional

Our Landing Page URL and Our Email HTML URL are required.

The other reference columns depend on the selected reference mode.

Support .xlsx files initially. Legacy .xls support can be added later.

4. Three Reference Modes

This is a very important requirement.

The application must support three modes.

Mode A: Client Landing Page Reference

Sometimes the client provides only a landing page URL.

In this case:

Visit the client landing page.
Extract the original Title.
Extract the original Abstract.
Visit our landing page.
Extract our Title and Abstract.
Visit our email page.
Extract its Title and Abstract.
Compare both internal pages against the client reference.

The client page is the original source of truth.

Mode B: Excel Title and Abstract Reference

Sometimes the client provides the original Title and Abstract directly in Excel.

In this case:

Select the Excel Title column.
Select the Excel Abstract column.
Select our landing page URL.
Select our email page URL.
Extract content from our landing and email pages.
Compare both internal pages against the Excel Title and Abstract.

IMPORTANT:

Do not visit or extract the client landing page in this mode.
The client URL should be optional.
Excel Title and Abstract are the reference.
Do not unnecessarily fetch the client website.
Mode C: Hybrid Reference Mode

Sometimes the client provides only the Title in Excel but the Abstract must come from the client landing page, or vice versa.

Therefore, add independent reference-source dropdowns:

Reference Title Source:

Client Landing Page
Excel

Reference Abstract Source:

Client Landing Page
Excel

The application must fetch only the sources actually required.

For example:

Title from Excel.
Abstract from Client Landing Page.

This should work independently for each field.

5. Most Important Requirement: Accurate Content Extraction

DO NOT compare the entire webpage.

A webpage contains many irrelevant elements:

Navigation menus.
Forms.
First name and last name fields.
Email and phone fields.
Submit buttons.
Privacy policies.
Footer content.
Header content.
Other unrelated text.

We only want the actual Title and Abstract.

Example from my screenshot

The client landing page had this structure:

Title:

"State of Sales: Professional Services Edition"

Abstract:

"Insights and trends from 177 professional services sales professionals around the world."

Then an introductory paragraph:

"Professional services sales teams face a widening gap between commercial expectations and seller capacity as deal cycles lengthen, buying groups expand, and clients want clearer proof of value. Leading firms are using AI to recover time, sharpen execution, and create more capacity for the high-value, relationship-driven work that drives results. Read the report to discover how:"

Then four bullet points:

Seller capacity is under strain.
Account expansion is becoming a higher priority.
Buyer demands are rising.
AI is becoming a core lever for seller productivity.

The entire relevant content in the red-marked area should be considered the Abstract.

The form on the right side must be ignored.

Extraction strategy

I do not want a system that assumes every website has the same HTML structure.

Different clients may use different landing page designs.

Build a flexible extraction system with:

A. Automatic extraction

Look for H1 elements for the title.
Check relevant meta descriptions.
Look for likely abstract sections.
Extract relevant paragraphs and bullet points.
Ignore forms, navigation, footer, buttons, scripts, styles, and unrelated elements.

B. Manual extraction This is extremely important.

Add a visual content selection feature.

After fetching a webpage, show its extracted text in the application.

Allow me to select or tick the exact content I want:

Title.
Introductory paragraph.
Abstract paragraphs.
Abstract bullet points.

I should be able to exclude:

Form labels.
Buttons.
Navigation.
Footer.
Irrelevant text.

C. Custom CSS selectors

Allow optional CSS selectors for:

Title.
Abstract.

Examples:

h1
.page-title
.abstract
#summary

Allow multiple selected elements for an Abstract.

D. Preview before comparison

Before comparing pages, show the extracted Title and Abstract so I can verify that the correct content was selected.

Never silently assume that automatic extraction is correct.

6. Comparison Logic

For each Excel row, compare:

Reference Title vs Our Landing Title.

Reference Title vs Our Email Title.

Reference Abstract vs Our Landing Abstract.

Reference Abstract vs Our Email Abstract.

Do not compare our landing page against our email page as the primary QA reference. Both must be checked against the original reference.

Comparison requirements

Show:

Exact match.
Mismatch.
Missing content.
Additional content.
Changed words.
Missing sentences.
Similarity percentage.

Use normalized comparison that ignores irrelevant differences such as:

Uppercase/lowercase.
Extra spaces.
HTML entities.
Unnecessary whitespace.

However, do not silently ignore meaningful content changes.

Provide two comparison methods if practical:

Exact normalized comparison.
Similarity comparison.

A high similarity score must not automatically mean PASS if important content is missing.

The QA status should clearly distinguish:

PASS
MISMATCH
CONTENT MISSING
REFERENCE MISSING
EXTRA CONTENT
NEEDS MANUAL REVIEW
FETCH ERROR
